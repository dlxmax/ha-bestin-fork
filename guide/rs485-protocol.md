# BESTIN RS-485 프로토콜 입문

월패드가 가전·설비와 RS-485 로 주고받는 프레임이 어떻게 생겼고 어떻게 동작하는지 정리했어요. 한 대의 월패드(EW11 두 대)에서 확인한 내용이라, 다른 모델은 다를 수 있어요.

## 1. 버스

월패드는 서로 독립된 RS-485 버스 여러 개를 가지고 있어요 (9600 baud, 8N1). 버스마다 장치 주소가 따로라서, 같은 주소(`0x31`)가 버스에 따라 다른 장치예요. EW11 어댑터가 버스를 TCP 로 내보내요 (포트 `8899`). EW11 은 받은 바이트를 연결된 모든 클라이언트에 그대로 보내므로, 클라이언트가 둘이면 서로의 트래픽도 보여요.

| 버스 | 장치 | 주소(헤더) |
|---|---|---|
| 제어 | 난방 컨트롤러 | `28` |
| | 가스 밸브 1, 2 | `31`, `32` (10바이트) |
| | 환기 | `61` (10바이트) |
| 에너지 | 조명·콘센트 | `31` (가변 길이) |
| | 대기전력 차단 장치 | `41`–`43` |
| | HEMS (계량기) | `D1` |

이 통합이 모르는 버스(스마트 스위치, 엘리베이터 호출 등)도 있어요.

## 2. 프레임

모든 프레임은 `02` 로 시작하고 체크섬 한 바이트로 끝나요. 모양은 두 가지예요.

**가변 길이**: `02 <헤더> <길이> <명령> <순번> <데이터…> <체크섬>`. 길이는 시작 바이트와 체크섬을 포함한 프레임 전체 바이트 수예요.

**고정 10바이트** (가스 밸브 `31`/`32`, 환기 `61`, 도어락 `41`): `02 <헤더> <명령> <순번> <데이터 5바이트> <체크섬>`. 길이 바이트가 없어요.

```
가변 : 02 41 08 91 6b 01 16 a2                 (대기전력 차단 장치 답)
고정 : 02 32 00 52 00 00 00 00 00 66           (가스 밸브 2 상태 요청)
```

- **체크섬**: `c = 3; 마지막 바이트를 뺀 모든 바이트에 대해 c = ((c ^ byte) + 1) & 0xFF`. 결과가 마지막 바이트예요.
- **요청과 답**: 월패드가 요청을 보내고 장치가 답해요. 답의 명령은 요청 명령에 `0x80` 을 더한 값이에요 (`11`→`91`, `01`→`81`, `21`→`A1`, `22`→`A2`, `42`→`C2`, 고정 형식은 `00`→`80`, `02`→`82`). 답은 요청의 순번을 그대로 돌려줘요.
- **순번**: 월패드가 명령을 보낼 때마다 바뀌는 한 바이트예요. 이 통합은 명령을 보낸 뒤 같은 순번의 답이 오는지 확인해요.
- **정기 요청**: 월패드는 쉬지 않고 장치를 불러요. 난방 요약은 약 1초마다, 장치 정보는 5분마다, 외기 온도는 30분마다예요. 장치는 불릴 때만 말하고, 이 통합은 듣기만 하면 상태를 얻어요.

### 프레임 찾기

바이트 스트림에는 프레임 경계 표시가 없어요. `02` 를 찾고, 다음 바이트가 알려진 헤더인지 보고, 헤더가 `31`/`32`/`41` 이고 그다음 바이트가 `00 01 02 80 81 82` 중 하나이거나 헤더가 `61`/`17` 이면 10바이트, 아니면 세 번째 바이트를 길이로 읽어요. `02` 는 데이터에도 나올 수 있으므로 앞 프레임에서 길이나 체크섬이 맞지 않으면 한 바이트만 버리고 다시 찾아요. 가스 밸브 응답의 `80` 처럼 큰 값이 길이 자리에 오면 프레임 여러 개를 삼키므로, 고정 길이 장치를 헤더로 먼저 가려내는 게 중요해요.

## 3. 장치별

### 난방 컨트롤러 (`28`, 제어 버스)

방마다 온도조절기가 있어요 (이 월패드는 5개, 방 번호 1–5).

| 명령 | 방향 | 내용 |
|---|---|---|
| `11` → `91` | 방 하나 | 요청은 7바이트 `02 28 07 11 <순번> <방> <체크섬>`. 답(16바이트): 바이트 5 = 방, 6 = 플래그 (비트0 켜짐, 비트4 밸브 열림 = 지금 난방 중), 7 = 설정 온도 (비트 0–5 정수 °C, 비트 6 = +0.5), 8–9 = 현재 온도 × 10 (2바이트 빅엔디언) |
| `12` | 설정 | 14바이트. 바이트 5 = 방, 6 = `01` 켜기 / `02` 끄기, 7 = 설정 온도 (위와 같은 인코딩) |
| `21` → `A1` | 전체 방 | 시계 + 방마다 4바이트 (모드+밸브, 설정, 현재 2바이트). 약 1초마다 |
| `22` → `A2` | 전체 방 설정 | 본 것은 시계(10:02)만 담았어요. 답은 `A1` 과 같은 배치 |
| `01` → `81` | 장치 정보 | 18바이트 장치 정보: 방 수, 기능 플래그, 온도 범위, 제조사, 펌웨어 |
| `42` → `C2` | 외기 온도 | 월패드가 외기 온도를 보내고(`42`) 컨트롤러가 온도와 AI 모드로 답해요(`C2`) |

```
02 28 10 91 12 04 01 56 00 e9 00 25 00 00 00 26   방 4, 켜짐, 설정 22.5 °C, 현재 23.3 °C
```

방 하나의 `91` 은 길이 바이트가 `10` (16바이트)일 때만 온도조절기 상태예요. 길이가 다른 `28` 프레임(예: 18바이트 `81`)을 온도조절기로 읽으면 터무니없는 값이 나와요.

#### 장치 정보 `01` → `81`

월패드가 5분마다 묻고(`01`), 컨트롤러가 18바이트로 답해요. 온도 측정값이 아니라 **고정된 사양**이라 값이 바뀌지 않아요. 제어 버스(`28`)에서만 나와요.

```
02 28 12 81 12 | 05 1d 03 05 28 10 0e 04 16 01 01 06 | 9d
```

| 위치 | 이름 | 예시 | 설명 |
|---|---|---|---|
| 3 | 명령 | `81` | 장치 정보 답 (요청은 `01`) |
| 5 | 방 수 | `05` | 1–8 |
| 6 | 플래그 1 | `1d` | bit0 0.5° 단위, bit1 외출, bit2 취침, bit3 예약, bit4 일시정지 (상위 3비트는 0) |
| 7 | 플래그 2 | `03` | bit0 AI, bit1 외기온도, bit2 **보일러**, bit3 누수 (상위 4비트는 0) |
| 8 | 최소 온도 | `05` | 최소 설정 온도 °C (5–20) |
| 9 | 최대 온도 | `28` | 최대 설정 온도 °C (21–50) |
| 10 | 제조사 | `10` | 제조사 코드 (1 이상) |
| 11–13 | 펌웨어 날짜 | `0e 04 16` | 연(2000 + 값), 월, 일 (16진수 `16` = 22일) → 2014-04-22 |
| 14 | 펌웨어 빌드 번호 | `01` | |
| 15–16 | 프로토콜 버전 (주.부) | `01 06` | 1.6 |

예시의 해석: 5방, 0.5° 단위·취침·예약·일시정지 지원, 외출 미지원, AI·외기온도 지원, **보일러 없음**, 누수 센서 없음, 설정 범위 5–40 °C, 제조사 16. 보일러 온도가 아니에요: 이 월패드 버스에는 보일러 요청이 없고 `플래그 2` 의 보일러 비트도 꺼져 있어요. 길이가 `10`(16바이트)이 아니므로 온도조절기 `91` 로 읽으면 안 돼요.

#### 외기 온도 `42` → `C2`

월패드가 30분마다(:02, :32) 외기 온도를 보내고(`42`), 컨트롤러가 외기 온도와 AI 모드로 답해요(`C2`).

```
02 28 0b 42 70 | 01 02 00 00 00 | 1b          월패드 → 난방  (데이터: 플래그 1, 2 °C, 모드 0 = 변경 없음)
02 28 0a c2 70 | 02 01 32 23    | 88          난방 → 월패드
```

| 바이트 | 뜻 |
|---|---|
| 5 | 외기 온도: 비트 0–5 정수 °C (최대 60), 비트 6 = +0.5, 비트 7 = 음수 |
| 6 | AI 모드: 1 = 켬, 2 = 끔 |
| 7–8 | 뜻을 모르는 바이트예요 (`32 23`, 본 프레임마다 같았어요) |

월패드는 AI 모드를 **바꾸지 않아요**: 본 `42` 요청은 모두 AI 모드 자리에 "변경 없음"(`0`)을 담아요. 외기 온도는 센서 값이 아니라 단지 서버가 월패드에 보내는 날씨 정보의 현재 기온이에요 (발표 날짜가 오늘일 때만, 기온 하나만 전달해서 날씨 센서와 조금 달라요). AI 모드가 실제로 무엇을 하는지는 확인하지 못했어요.

### 가스 밸브 (`31`, `32`, 고정 10바이트)

밸브마다 헤더가 하나예요 (`31` = 첫째, `32` = 둘째). 명령은 상태 요청 `00` 과 닫기 `02` 뿐이에요. 열기 명령은 알려진 게 없어요 (버스로는 닫기만 해요).

```
요청 : 02 32 00 52 00 00 00 00 00 66
답   : 02 32 80 52 80 01 00 00 00 67    바이트 5: 0 닫힘, 1 열림, 2 동작 중
```

### 환기 (`61`, 고정 10바이트)

| 명령 | 바이트 5, 6 | 뜻 |
|---|---|---|
| `00` | — | 상태 요청 |
| `01` | `<켜짐 0/1> 01` | 켜기·끄기 |
| `03` | `00 <속도 1–3>` | 풍속 |
| `07` | `<10 또는 00> …` | 자연 환기 켜기·끄기 |

답 `80` 의 바이트 5: 비트0 켜짐, 비트4 자연 환기. 바이트 6: 풍속.

### 조명·콘센트 (`31`, 가변 길이, 에너지 버스)

방마다 요청해요 (`02 31 07 11 <순번> <방> <체크섬>`). 답은 30바이트예요: 바이트 5 = 방 (하위 4비트), 6 = 조명 비트마스크 (비트 N = 조명 N), 7 = 콘센트 비트 0–1 + 비트 4 = 대기전력 차단, 8–11 = 콘센트 두 개의 차단 기준값 × 10, 12–13 = `dcvalue` × 10 (뜻 미확인), 14부터 콘센트마다 2바이트 소비전력 × 10. 1번 방은 조명 4개와 콘센트 3개, 나머지는 2개씩이에요.

제어 명령(13바이트, 명령 `01`): 바이트 5 = 방, 6 = `(1 << 조명번호) | 80`(켜기) 또는 `1 << 조명번호`(끄기), 7 = 콘센트 비트, 8 = 대기전력 차단 (`83` 켜기 / `03` 끄기), 11 = `04` (조명 켜기) 또는 `09 << 콘센트번호` (콘센트 켜기), 끄기는 `00`.

### 대기전력 차단 장치 (`41`–`43`, 에너지 버스)

요청 `02 4x 07 11 <순번> <회로 수> <체크섬>`, 답 `02 4x <길이> 91 <순번> <회로 수> <회로마다 상태 1바이트> <체크섬>` (상태 바이트: 비트 0–1 모드, 2–3 차단 여부, 4–5 기준값 상태, 6–7 과부하). 같은 헤더 `41` 이 고정 10바이트(`02 41 00 …`)이면 도어락이에요.

상태 프레임의 예 (`02 41 08 91 6b 01 16 a2`): 바이트 5 = 회로 수, 6… = 회로마다 상태 1바이트.

| 비트 | 값 | 뜻 |
|---|---|---|
| 0–1 | `1` / `2` | mode true / mode false. 장치의 자동 차단 모드 스위치로 보이지만 확인하지 못했어요. 본 장치는 모두 false |
| 2–3 | `4` / `8` | 차단 안 됨 / 차단됨 (회로 전원이 끊김) |
| 4–5 | `0` / `16` 또는 `32` | "cut-off value status". 차단 기준값이 설정되었다는 뜻으로 보이지만 확인하지 못했고, 기준값 자체는 이 프레임에 없어요 |
| 6–7 | `0` / `64` | 정상 / 과부하 오류 |

예: `0x16` = `0001 0110` → mode false, 차단 안 됨, cut-off value status true, 과부하 없음. 확인한 월패드의 세 장치가 모두 이 값이에요.

### HEMS 계량기 (`D1`, 에너지 버스)

요청 `D1 … 02` 에 48바이트 `82` 로 답해요. 계량기마다 누계 4바이트와 실시간 값 2바이트가 있고, 값은 BCD(16진수로 읽으면 10진수 숫자)예요. 누계는 바이트 8–11 전기, 16–19 수도, 24–27 온수, 32–35 가스, 40–43 난방이고, 실시간 값은 바이트 13, 21, 29, 37, 45 에서 시작하는 2바이트예요 (같은 순서, 8바이트 간격). 34바이트 형식(온수·난방 없음)은 수도 누계가 17–19(3바이트), 가스 누계가 25–28 이에요.

## 4. 다른 형식

이 통합에는 `Gen2`(헤더 `30`–`3F`)와 `AIO`(헤더 `50`–`5F`, `17`) 형식의 조명·콘센트 코드도 있어요. 이 월패드에서는 나오지 않아서 여기서는 다루지 않아요. 코드(`controller.py` 의 `parse_state_gen2`, `parse_state_aio`)가 설명이에요.

## 5. 프레임 목록

월패드 한 대의 두 EW11 어댑터에서 실제로 본 프레임 전체예요. 키는 `헤더/길이(10진수)/명령` 형식이에요 (진단 정보의 `packet_types` 와 같아요).

## 6. 모르는 것

- 난방 `91` 의 바이트 10–14 와 `A1` 의 방 항목 일부, 외기 온도 답 `C2` 의 바이트 7–8 (`32 23`) 은 뜻을 모르고, 값이 바뀌는 것도 보지 못했어요.
- 대기전력 차단 장치의 `mode` 와 `cutvalue` 비트는 추정이에요.
- 프레임이 이해되지 않으면 진단 정보의 `packet_types` 에서 `ignored` 가 0 이 아닌 키를 이슈에 올려 주세요.
